# Harness 质量与资源研究

研究相同业务任务能否以更少资源保持约定效果。目标资产在业务仓单处维护，当前工作树用 business:<id>，固定 Git tag/commit 为只读对照；实际执行步骤由 compute-variant-research Skill 维护。

## 从实际成本出发

先读代表 Run 的真实输出和工具结果，再检查有关决策、重复查询、长上下文、子任务与外部等待。调用多不证明浪费；没有 Run 可以策划补采，不能伪造诊断。

优先减少没有新增信息的请求、按阶段读取资料、复用有效结果或把确定步骤交代码。保留关键复核、纠错与异常，不丢失失败信息。默认继承业务模型和推理档位，只有用户明确选择才改变，管理助手模型不代替业务模型。

no-compute、low-compute、medium-compute 和 full-compute 只是研究目标，不是平台等级或已验证收益。声称无模型调用需要实际请求证据，运行路由变化必须记录。

## 固定比较口径

明确假设、真实 Case、关键任务、独立次数、允许的质量变化、资源指标与预期收益；选择理由与风险对应，默认阈值不保证统计充分。新增 Case 先保存再开始比较，不能看到结果后降低标准。

比较双方各自核对业务来源与冻结 Run，保持 Case、模型与外部条件一致。历史 Run 可诊断，不追认为新一轮独立比较，同一 Run 重复选择不增加独立次数。工作树允许 dirty，其实际来源与内容由本次 Run 记录，不强制提交或建 tag。

资源分别记录主子 Session、重试、评审和外部模型的调用、Token、耗时及实际可采集费用或硬件；未采集项保持未知，不将 Token 换算成硬件算力或账单。共享外部后端、负载和观测缺口单列为混淆因素。

## 较弱模型与决策模型

先固定真实业务基线，再把复杂判断分为清楚的小步骤，让代码承担参数绑定、固定处理与状态管理，候选模型重跑相同任务。off 可作同模型低推理压力测试，不能据此把同一模型称为小模型或外推其他模型收益。

强模型基线与小步骤方法可参考 [OpenAI 实践指南](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/)，工具选择参考 [Anthropic 工具设计](https://www.anthropic.com/engineering/writing-tools-for-agents)。[工具 Schema 与小模型适配研究](https://arxiv.org/abs/2510.07248v3)的特定实验不代表本项目收益，均须回到实际任务验证。

区分确定规则、有限选项判断和开放分析。有限选项模型可以研究路由或补充信息决策，不能代替完整研判与工具结果。共同检查误分流、不确定回退、中文和边界输入；单个判断点通过不能外推整个 Harness 等效。

## 按需进入 KEV

仅策划或 plan_only 保持只读；已有实施授权则从首个未完成阶段继续，不因切换 Skill 重复取确认或重做成功步骤。

1. 真实 Run 的决策前材料由 decision-sample-extraction、kev-trace-pipeline 抽取与复核；历史动作和未来结果不能当成当时可见状态或正确标签。
2. kev-dataset-audit 检查来源、标签与 train/development/calibration/test 四分区。关联样本、同 Run/Session 和等价输入不跨用途，拆行不能制造独立测试。
3. kev-training 固定 checkpoint、tokenizer、输入构造器、代码与配方，完成真实编码检查后，通过已授权原生命令卡执行训练、开发评估、校准与独立测试。模型路由不自动等于可训练权重，服务器探测不证明真实认证、GPU或依赖可用。
4. kev-deploy 核对实际服务、模型工件与工具合同，再把路由接入所属业务 Harness。保存实际文件、恢复依赖、摘要与回执，不能用配置声明或公开初始化 checkpoint 代替本次训练。
5. 按当前资产编辑、构建和实例重载合同使代码生效，再运行两侧新的业务 Run，使用 runs/compare 判断质量、资源与限制。没有平台训练调度动作就复用已有原生执行工具，不编造接口、自动归档或冻结状态。

官方 KEV 训练和部署快照按各自 Skill 固定来源读取，不能直接修改上游副本。原生 LoRA 配方与官方 Modal 配方分开核对，数据、编码、训练、服务和业务等效分别取证。只有已有 checkpoint 且只要求部署时直接进入 kev-deploy，不强制重新训练。

## 判断与结束

关键任务退步、双方失败、重复不足、输入或环境变化、资源未知或收益不足，均不能认定等效。保留失败、反例和 continue/inconclusive，不放宽原口径。结论只覆盖实际比较的任务与条件，不自动发布、切换实例、推送 Git 或外推所有环境。
