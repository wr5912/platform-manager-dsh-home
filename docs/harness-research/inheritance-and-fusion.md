# 来源固定、能力继承与集成

业务 Harness 在 business-agents 的 `agents/<id>/` 单处维护。当前工作树使用 `business:<id>`，固定 Git tag/commit 使用同一选择器的 @ 引用；固定来源只读。Git 提交记录版本，实际装载由实例回执证明，二者不能互相替代。

## 核对来源与目标

通过 business/detail、business/read 核对有关来源的完整内容、提交与文件。保留用户选定的来源，不将程序 HEAD、目录名或历史比较起点当作所选版本本身。dirty 工作树可以使用，但不能冒称已固定且可恢复。

按任务核对有效的已有能力和并行来源，说明继承、舍弃与替代依据。没有核对远端或其他工作树就限定范围，不声明覆盖全部来源；资源优化名称、训练完成或一次成功不能作为排除有效能力的依据。

只读策划给出取舍与验证方法后结束。实施时目标为授权的业务仓当前工作树；已有 Harness 按 edit/read → edit/preview → edit/apply 更新完整正文与引用，新 Agent 通过原生文件工具创建原生资产并登记。固定来源保持不变，不复制版本目录或另造融合状态。

## 内容与依赖一致

同时核对源码、生成物、Preset、Skill、Plugin、模型、MCP 服务 ID 与工具选择、运行依赖及项目种子。保留目标独有变化；共同祖先未知时明确取舍，不能猜祖先或机械还原全部文件。

文件差异不能证明语义兼容，也无法发现未列入的来源。截断正文、缺失文件和二进制元数据不能代替完整内容；冲突先重新读取，不覆盖并行修改。移动与直接引用同批更新。

依赖和构建使用现有 assets/dependencies/prepare、assets/build-preview、assets/build，核对真实制品与当前来源。来源自身测试不能代替目标集成；构建通过、实际装载与业务效果分别取证，不运行任意来源脚本绕过当前入口。

## 行为验证与结论

通过明确目标实例重载回执和新 Session 验证各来源的关键能力、共同场景及受影响回归。Web、MCP、模型与业务产物分别核对，外部依赖不可用时限定结论。

只在来源、当前资产、Case 与真实 Run 相符时认定对应行为已验证。需要保存结论时维护所属业务文档并引用实际证据，不改写历史 Run，也不自动提交、推送、切换其他实例或宣布发布。
