# 训练工件接入 Harness 变体

1. 记录训练输出：固定 KEV 代码、base 与 checkpoint 来源、数据/输入构造版本、温度、阈值、权重及 tokenizer 摘要、真实执行日志。只有实际存在的工件才登记。
2. 在用户明确选择的执行环境部署推理服务。交给本地 kev-deploy 入口，按需读取其完整官方参考；Modal 示例不是 SSH 服务器通用部署命令，部署、远端上传、付费资源和清理各按当前授权办理。
3. 核对真实返回合同：state/questions、choice/noul/score、概率键、延迟、超限和失败。服务端合法候选校验、参数绑定、确定性规则及低置信回退保留在代码中。离线与在线复用相同状态/候选构造器。
4. 从当前公开 SDK 与业务 Harness 核对语言/决策角色和实际工件摘要，再从真实 MCP 目录取得已注册的工具 Schema；按实际运行库合同调用已部署的 KEV 服务；不要猜工具名或用任意 HTTP 绕过运行库。角色与摘要登记不等于推理服务可达、业务版本已装载或效果通过。
5. 在授权业务仓当前工作树接入，固定 tag/commit 只读作比较。按 compute-variant-research 通过当前编辑、构建、实例重载与真实 Run 分别核对，编译成功不证明已装载。
6. 比较父版、代码基线和 KEV 变体的新 Run。计入特征整理、推理、回退、重试和恢复成本；两侧都失败不能证明等效。满足本次约定口径后报告实际收益与限制，训练脚本不代填人员确认。

训练材料按实际训练请求和回执保存真实身份、文件与摘要；公开请求沿用的 parent_experiment_id 承载实际 business 来源，不能伪造已不存在的平台状态。保留原始日志、四分区数据、校准与测试报告及实际工件，回执只引用数据根内文件和摘要。回收核验通过不替代真实执行、人员标签复核、服务或业务比较。

训练作业及 KEV 服务按当前真实执行能力办理。明确 `generation_intent=implement` 的任务可沿用原生执行工具，保存可恢复作业身份；仅策划仍不执行。程序没有训练调度 API 不等于已授权的原生执行路径不存在，也不得据此伪造接口或训练结果。
